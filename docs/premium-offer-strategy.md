# Premium Offer Strategy

## Executive Decision

Do not add a public `$2,500` package right now.

The correct move is to mention implementation setup only after demo or pilot qualification. The `$2,500` number may be used internally as a sales-call-only quote anchor for serious Operational Infrastructure clients, but it is not public checkout pricing and should not appear as a public pricing card.

No Square, Stripe, PayPal, checkout, or payment link should be created for this offer until Wallace explicitly approves the final offer, scope, and placement.

## Current Offer Ladder

### After-Hours Capture - `$97/mo`

Entry coverage for businesses that need Gideon to capture calls when the team is closed. Public copy should keep this easy to understand: after-hours answering, caller details, urgency flagging, lead summaries, and simple appointment request capture.

### Revenue Recovery System - `$497/mo`

The main conversion tier. This is the core recovery layer for 24/7 and overflow call capture, missed-call recovery, speed-to-lead support, lead notifications, appointment request capture, hot-lead alerts, and monthly revenue recovery reporting.

### Operational Infrastructure - `$997+/mo`

The premium monthly layer. It implies custom call-flow design, scoped workflow automation, reminder and follow-up logic, operational notification mapping, CTOS-backed visibility as available, optimization review, and founder/operator review.

### Public Ladder Rule

The public ladder should stay simple. The website should lead with the monthly tiers above and avoid introducing a large public implementation price before a prospect has context. A public `$2,500` card would add friction, create monthly-vs-setup confusion, and imply a checkout path that does not exist yet.

## Premium Offer Recommendation

Package name: **Operational Infrastructure Setup**

Alternative name: **Revenue Recovery Infrastructure Setup**

Positioning:

Done-for-you call-flow and workflow setup for businesses that need Gideon configured around real operations before launch.

This is an implementation offer, not a fourth public plan. It should be presented after qualification when the business has a meaningful workflow, routing, handoff, or operational visibility problem that justifies extra setup work.

## What It Includes

### Real Now

- business intake
- services, hours, and service-area setup
- greeting and call-flow design
- urgency and emergency rules
- appointment request handling
- handoff and notification mapping
- setup review before go-live
- first-week QA and tuning
- founder/operator review

### Requires Backend, Provider, Or Manual Approval

- provider activation
- call routing or forwarding
- SMS/email notification workflows
- CRM/CTOS visibility
- direct booking integrations
- missed-call recovery automations
- follow-up workflows

These items must be scoped and approved before they are promised as active. Do not imply that provider routing, backend sync, SMS/email, webhooks, CTOS, CRM, or booking automation is live before the actual implementation exists and has been approved.

## Sales-Call-Only Quote Guidance

`$2,500` can be used as a quote anchor only after workflow review.

Guidance:

- Frame it as one-time implementation, not monthly.
- Pair it with `$997+/mo` Operational Infrastructure.
- Use it only for serious clients with meaningful workflow, routing, handoff, integration, or operational visibility needs.
- Do not display it as a checkout price yet.
- Do not create a payment link until Wallace approves the exact scope and offer language.

## Risks

- Public `$2,500` could scare off smaller leads before they understand the value.
- Monthly pricing vs. setup pricing could become confusing.
- Public implementation pricing could overpromise provider/backend activation.
- A checkout page without matching implementation scope would create a payment mismatch.
- Selling implementation before scope is known could underprice complex work or create delivery risk.
